# GoTap 自动部署说明

## 部署触发条件

本项目使用 Git `post-push` 钩子。只有将代码成功推送到远端 `v2` 分支后，钩子才会通过 SSH 连接生产服务器，执行以下操作：

1. 进入生产服务器上的项目目录。
2. 使用 `git pull --ff-only origin v2` 拉取最新代码。
3. 使用 Docker Compose 重建并重启管理 API 服务。

推送 `master`、`main` 或其他分支不会触发生产部署。

## 本地启用

在项目根目录执行：

```bash
git config core.hooksPath .githooks
cp .githooks/deploy.local.sh.example .githooks/deploy.local.sh
chmod 600 .githooks/deploy.local.sh
```

然后编辑 `.githooks/deploy.local.sh`，填写以下配置：

- `GOTAP_DEPLOY_SSH_USER`：生产服务器 SSH 登录用户名。
- `GOTAP_DEPLOY_REMOTE_HOST`：生产服务器地址。
- `GOTAP_DEPLOY_SSH_PORT`：SSH 登录端口。
- `GOTAP_DEPLOY_REPO_DIR`：生产服务器上的项目目录绝对路径。
- `GOTAP_DEPLOY_SSH_KEY`：可选的 SSH 私钥路径；留空时使用 `~/.ssh` 中的默认密钥。

配置文件包含服务器连接信息，已加入 `.gitignore`，禁止提交和推送。

## 安全与故障处理

钩子使用 `BatchMode=yes` 和 `StrictHostKeyChecking=yes`，不会在推送过程中等待密码或接受未知主机指纹。首次使用前，请先手动通过 SSH 连接一次生产服务器并确认其主机指纹。

代码推送成功与生产部署成功是两个独立结果。若部署失败，钩子会返回错误，但不会撤销已经完成的远端推送；请登录生产服务器检查 Git 工作区、SSH 权限和 Docker Compose 日志。
