# GoTap 自动部署说明

## 部署触发条件

本项目使用宝塔 Webhook 触发部署。推送到远端 `v2` 分支后，触发请求会调用宝塔 Webhook，由生产服务器执行以下操作：

1. 进入服务器上的 `/opt/gotap-source` 项目目录。
2. 使用 `git pull --ff-only origin v2` 拉取最新代码。
3. 如果 `admin/` 有变化，使用服务器 Node.js 24 构建并更新 Nginx 静态文件。
4. 使用 Docker Compose 重建并重启管理 API 服务。

推送 `master`、`main` 或其他分支不会触发生产部署。

## 管理后台前端更新

管理后台位于 `admin/` 目录。只有推送内容包含 `admin/` 文件变更时，部署钩子才会在生产服务器使用宝塔安装的 Node.js 24 和 `npm ci`、`npm run build` 构建前端，再将构建结果同步到 Nginx 静态目录；本地不需要安装依赖或上传文件，仅修改 Python 后端不会重新打包前端。

每次前端发布需要递增 `admin/package.json` 的补丁版本号，并同步提交 `admin/package-lock.json`：

```bash
npm version patch --no-git-tag-version --prefix admin
```

构建结果会生成 `/admin/assets/version.json`。管理后台右上角会显示当前版本，并定期检查该文件；发现新版本时显示红点，点击后刷新页面加载新版本。

## 本地启用

在项目根目录执行：

```bash
git config core.hooksPath .githooks
cp .githooks/deploy.local.sh.example .githooks/deploy.local.sh
chmod 600 .githooks/deploy.local.sh
```

然后编辑 `.githooks/deploy.local.sh`，填写以下配置：

- `GOTAP_DEPLOY_WEBHOOK_URL`：宝塔 Webhook 完整地址，包含 `access_key` 密钥。

配置文件包含服务器连接信息，已加入 `.gitignore`，禁止提交和推送。

## 远端推送后自动触发

Git 原生不会自动执行仓库中的 `post-push` 文件；要让远端仓库每次推送 `v2` 后触发宝塔 Webhook，请在 GitHub 仓库中新增 Webhook：

1. 打开仓库的 `Settings` → `Webhooks` → `Add webhook`。
2. 将宝塔 Webhook 完整地址（包含 `access_key`）填写到 `Payload URL`。
3. `Content type` 选择 `application/json`，事件选择 `Just the push event`，并启用 Webhook。
4. 推送 `v2` 后，在 GitHub 的 Webhook `Recent Deliveries` 查看请求结果；服务器端可查看宝塔 Webhook 日志。

宝塔 Webhook 脚本自身会固定拉取 `origin/v2`，因此不需要向 Webhook 地址追加 `param` 参数。Webhook 地址包含密钥，只能保存在 GitHub Webhook 配置或本地忽略配置中，不得写入代码库。

## 安全与故障处理

Webhook 地址包含密钥，只能保存在本地忽略配置中，不得提交到仓库。建议在宝塔面板中限制 Webhook 的访问来源，并定期更换密钥。

代码推送成功与生产部署成功是两个独立结果。若部署失败，钩子会返回错误，但不会撤销已经完成的远端推送；请登录生产服务器检查 Git 工作区、SSH 权限和 Docker Compose 日志。
