# 文档格式互转模块开发说明

本文记录 GoTap“文档格式互转”模块的产品边界、技术方案和续作状态。Codex CLI 会话中断或更换开发者后，先读本文，再从“实施顺序”继续。

## 需求范围

- 支持 DOC、DOCX 与 PDF 互转。
- 支持 PPT、PPTX 与 PDF 互转。
- 客户端支持选择文件和拖放文件，显示转换记录及下载结果。
- 转换记录属于当前登录用户；失败任务也应可查。
- 管理后台通过已有模块管理开关控制该功能是否对客户端开放。
- 本阶段先做方案与开发说明，尚未实现转换功能、数据库表、上传接口或依赖部署。

## 仓库现状

- 客户端是 Tauri 2 + React + TypeScript，`src/App.tsx` 目前用 `module_key` 选择模块；自动点击器是已实现模块，其余模块显示占位页。
- 管理 API 位于 `management-api/`，使用 FastAPI、SQLite、Docker Compose；登录用户通过 `current_user` 鉴权。
- 管理后台已有模块 CRUD 和启用/关闭能力。`GET /v1/modules` 返回启用模块；新增模块仍需客户端实现同名 `module_key`。
- API 已有 `UploadFile`、`FileResponse`、`BackgroundTasks` 使用范例，可参照反馈附件/客户端发布包上传代码。
- API 容器基于 `python:3.12-slim`；持久化目录是 `./data:/data`。
- Python 现有依赖没有 Office 文档转换引擎。

## 技术决策建议

### 转换引擎

采用“FastAPI 编排 + LibreOffice headless 实际转换”的方案，不用纯 Python 库承担 Office/PDF 排版转换。`python-docx`、`python-pptx` 主要用于编辑 OOXML，不能稳定复现复杂文档布局；`pypdf` 也不能把 PDF 还原成可编辑的 DOCX/PPTX。

在 API Docker 镜像安装固定版本的 LibreOffice（含 Writer、Impress 所需组件及字体），由 Python 通过 `subprocess` 在独立临时目录调用 `soffice --headless --convert-to ...`。转换时必须限制并发、执行超时、内存/CPU/磁盘使用和输出文件大小；每个任务使用独立 profile 目录，避免多个 LibreOffice 进程争用用户配置。

### 格式能力和质量承诺

- DOC/DOCX -> PDF：LibreOffice Writer 转换。
- PPT/PPTX -> PDF：LibreOffice Impress 转换。
- PDF -> DOCX：LibreOffice 可尝试导入，但复杂 PDF 的版面、表格和可编辑性不能保证；上线前用真实样本评估。不要宣传为无损还原。
- PDF -> PPTX：LibreOffice 的 PDF 导入通常基于 Draw，可能按页面生成图形/背景，不等于恢复原始演示文稿结构。必须先用真实样本验证可用性，并在界面明确结果限制。
- 输入输出方向都应由实际验证矩阵决定。若 PDF -> Office 质量不可接受，第一阶段应先发布 Office -> PDF；反向转换作为受限的“尽力转换”或后续阶段，而不要静默提供质量不合格的结果。

开发开始前至少准备 DOC、DOCX、PPT、PPTX、文本型 PDF、扫描 PDF、含表格/图片/字体的样本，覆盖中文字体和跨页布局。

## 方案架构

1. 客户端注册 `module_key=document_converter`（或最终确认的标识），保留公共应用头部/主题/账户菜单，模块主体实现拖放上传、选择文件、格式方向、任务状态和记录列表。
2. 客户端把文件以 multipart/form-data 上传到 FastAPI。服务端只接受允许的扩展名与 MIME 候选值；扩展名、文件签名、可解析性需要交叉校验，不能信任浏览器提供的 MIME。
3. FastAPI 创建唯一任务 ID，保存用户 ID、原文件名、输入/输出格式、状态、大小、时间和错误摘要；输入文件写入 `/data/conversions/{user_id}/{job_id}/`，文件名使用服务端生成的 ID，不使用用户路径。
4. 对转换执行使用有界后台工作队列。MVP 可用进程内有限线程池/任务队列，但需在 API 重启后将遗留 `queued/running` 任务标为失败或可重试；若要多 API 副本、可恢复队列，再引入 Redis/Celery 等外部队列，当前不建议为单实例过早增加基础设施。
5. 工作线程在隔离临时目录运行 LibreOffice，记录开始/完成/耗时/退出码；成功后保存结果路径和文件大小，失败时返回安全、可读的错误摘要，不暴露服务器路径/命令行/敏感信息。
6. 客户端定时查询任务状态（或后续增加 SSE），成功后调用鉴权下载接口。下载接口必须验证任务所有者、任务成功状态和文件确实位于用户存储根目录内。
7. 管理 API 定时清理过期输入、输出和记录。建议初始保留 7 天，单文件 50 MB、每用户最多 3 个并发任务、总任务超时 120 秒；这些数值需结合服务器资源测算后做成配置。

## 建议 API 草案

- `POST /v1/conversions`：认证 multipart 上传，参数含 `file`、`target_format`。返回 `job_id`、`status=queued`、源/目标格式及时间。
- `GET /v1/conversions`：当前用户任务记录分页列表，可按状态过滤。
- `GET /v1/conversions/{job_id}`：当前用户任务状态和结果元信息。
- `GET /v1/conversions/{job_id}/download`：当前用户下载成功结果；使用安全生成的下载文件名和正确 Content-Type。
- `DELETE /v1/conversions/{job_id}`：可选；用户删除记录并清理对应文件。是否纳入第一版可在开发前确认。

数据库建议独立 `document_conversion_jobs` 表：`id`、`user_id` 外键、`source_name`、`source_format`、`target_format`、`input_path`、`output_path`、`input_size`、`output_size`、`status`、`error_message`、`created_at`、`started_at`、`finished_at`、`expires_at`。为 `(user_id, created_at)` 和 `(status, created_at)` 建索引。状态建议 `queued`、`running`、`succeeded`、`failed`、`expired`。

## 安全与可靠性要求

- 仅允许 `.doc`、`.docx`、`.ppt`、`.pptx`、`.pdf`，输出方向必须在服务端白名单映射中；不能把用户输入直接拼入 shell 命令。
- 调用子进程时使用参数数组，不使用 `shell=True`；每任务独立目录/profile，超时后终止整个进程组。
- 防止路径穿越、伪造后缀、超大文件、压缩炸弹、恶意宏/嵌入对象和资源耗尽；在无网络、低权限临时目录中运行 LibreOffice。MVP 不执行 Office 宏。
- 所有记录、状态、下载操作都按用户 ID 授权；不能通过猜测 job_id 读取他人文件。
- 文件按过期时间自动清理，记录清理策略应说明隐私；日志不记录文件正文和认证信息。
- Docker 部署需固定 LibreOffice 包/镜像版本、安装中文字体并验证字形；镜像体积、升级和 CVE 扫描纳入运维说明。

## 界面建议

- 页面中心提供拖放区和“选择文件”按钮；拖入不支持的格式立即提示。
- 上传后显示文件名、大小、转换方向及开始/排队状态；运行中展示进度时应说明这是任务阶段进度，不伪造百分比。
- 转换记录列出时间、文件、方向、状态、下载/失败原因；支持刷新、分页和空状态。
- PDF -> DOCX/PPTX 的结果旁明确提示可能需要人工校对，复杂版式、扫描件和字体无法保证完整还原。
- 适配当前亮/暗主题，复用共享 `AppHeader` 和 `module-return-row` 的模块标题/返回模块列表布局。

## 实施顺序

1. 验证服务器 Docker 基础镜像可安装 LibreOffice 和中文字体；制作转换样本矩阵并记录质量，确认 MVP 是否含 PDF -> DOCX/PPTX。
2. 在 `management-api` 增加转换配置、数据表迁移/初始化、文件存储和过期清理。
3. 增加 LibreOffice 转换适配层与有界任务执行器；先写单元测试，再集成真实转换样本。
4. 增加鉴权上传、记录、状态和下载 API；测试用户隔离、格式校验、超时、失败清理和容器重启恢复行为。
5. 新增客户端 `DocumentConverterPage`，接入 `document_converter` 模块路由/分发和记录交互。
6. 增加 Docker/部署环境说明、资源限制与数据清理策略；验证生产服务不会因并发转换拖垮登录/反馈 API。
7. 若修改管理后台 `admin/`，按项目约定递增 `admin/package.json` 补丁版本并同步 lockfile；仅修改桌面客户端则按客户端发布流程更新版本并创建 `v*` 标签触发 GitHub Release。
8. 跑 FastAPI 单测、真实 LibreOffice 集成测试、客户端 typecheck/renderer 构建及完整部署检查。
